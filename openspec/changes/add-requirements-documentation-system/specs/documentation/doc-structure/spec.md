## Purpose

Defines where Project 1 documentation lives, how its files and directories are named, how the index and rubric traceability map are maintained, and how each AI model's document set is kept isolated across git branches.

## ADDED Requirements

### Requirement: Documentation Root

All Project 1 document content SHALL live under `docs/` at the repository root. Specification files under `openspec/specs/` define how documents are written; they SHALL NOT contain document content themselves.

#### Scenario: Document content written into a spec file

- **WHEN** an actual vision statement, persona, or 1-pager body is written into a file under `openspec/specs/`
- **THEN** it MUST be moved to the corresponding file under `docs/`, leaving only the authoring rules in the spec

#### Scenario: Document content written outside docs/

- **WHEN** a Project 1 deliverable is created at the repository root or in an ad-hoc directory
- **THEN** it MUST be relocated under `docs/` before the change is considered complete

### Requirement: Per-Product Directory Layout

Each explored product SHALL occupy one directory `docs/<product-slug>/`, where `<product-slug>` is kebab-case. Each product directory MUST contain `vision.md`, `personas.md`, a `one-pagers/` directory, and `sizing.md`.

#### Scenario: Second product is added

- **WHEN** the second of the two required products from `project1.md` is started
- **THEN** it MUST be created as a sibling directory `docs/<product-slug>/` using the identical internal layout, with no shared or cross-linked files

### Requirement: One-Pager File Naming

Each 1-pager SHALL be one file at `docs/<product-slug>/one-pagers/<NN>-<epic-slug>.md`, where `<NN>` is a zero-padded two-digit ordinal establishing reading order and `<epic-slug>` is kebab-case.

#### Scenario: Two 1-pagers claim the same ordinal

- **WHEN** a new 1-pager is added with an ordinal already in use
- **THEN** the ordinals MUST be renumbered so that every 1-pager in the directory has a unique ordinal

### Requirement: Model Isolation By Branch

Each AI model's document set SHALL live on its own git branch — `claude` and `agy` — with identical directory layouts. Document directories MUST NOT contain per-model subdirectories, and a branch MUST NOT contain another model's document set.

#### Scenario: Model outputs are mixed on one branch

- **WHEN** documents generated by a second model are committed onto a branch that already holds another model's set
- **THEN** they MUST be moved to that model's own branch, so each branch remains a single model's independent attempt

### Requirement: Documentation Index

`docs/README.md` SHALL exist and list every document in the repository with a one-line description, and SHALL map each rubric item from `project1.md` to the file or files that satisfy it.

#### Scenario: A document is added or renamed

- **WHEN** any file under `docs/` is created, renamed, or removed
- **THEN** `docs/README.md` MUST be updated in the same change so that the index never references a missing file and never omits an existing one

#### Scenario: A rubric item has no mapped file

- **WHEN** the index is reviewed and a rubric item from `project1.md` maps to no file
- **THEN** that gap MUST be recorded explicitly in the index as an open item rather than left unmapped

### Requirement: Undecided Product Name Placeholder

Until the product name is chosen, documents SHALL refer to the product using the single placeholder token `{{PRODUCT_NAME}}`. No other spelling, working title, or invented name may be used.

#### Scenario: Product name is chosen

- **WHEN** the team selects the final product name
- **THEN** every occurrence of `{{PRODUCT_NAME}}` across `docs/` MUST be replaced in one pass, and the index MUST record the chosen name

#### Scenario: An ad-hoc name appears in a document

- **WHEN** a document introduces a working product name instead of the placeholder
- **THEN** it MUST be replaced with `{{PRODUCT_NAME}}` so a single later substitution remains sufficient

### Requirement: Cross-Document Reference Integrity

Any persona referenced in a 1-pager SHALL be defined in that product's `personas.md`, and any 1-pager referenced from the index SHALL exist.

#### Scenario: A 1-pager names an undefined persona

- **WHEN** a functional requirement names a persona that does not appear in `personas.md`
- **THEN** either the persona MUST be added to `personas.md` under the persona rules, or the requirement MUST be reassigned to an existing persona
